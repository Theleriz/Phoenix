# Клиентское BLE-подключение датчиков

## Решение

Backend не подключается к датчикам напрямую и не должен: `imu-gateway`
уже трактуется как отдельный сетевой клиент API, аутентифицированный
`PHOENIX_GATEWAY_TOKEN` через HTTPS/WebSocket (см.
[`gateway-transport.md`](../imu/gateway-transport.md)). Поэтому физическое
место BLE-подключения не имеет значения для backend — важен только сетевой
доступ клиента до сервера и соответствие нормализованному контракту пакета
(`RawIMUPacket` в `services/imu-gateway/src/phoenix_imu_gateway/models.py`).

BLE-подключение выполняется на стороне пациента:

- в браузере через Web Bluetooth API (Chrome/Edge/Android) — без установки
  приложения, естественный путь для `patient-web`;
- нативным companion-приложением (например iOS/Swift), если понадобится
  поддержка платформ без Web Bluetooth (Safari/iOS его не поддерживает).

Гибрид — оба клиента одновременно, каждый шлёт один и тот же нормализованный
пакет на сервер — architecturally допустим и не считается костылём.

## Риск гибрида и как его снижать

Главный риск — расхождение BLE-логики (framing, resync, checksum,
sequence-numbering) между двумя независимыми реализациями (JS/TS и Swift).
Формат реального пакета уже расходился с изначально заявленной спецификацией
на этапе первого живого теста (см.
[`docs/imu/current-script-audit.md`](../imu/current-script-audit.md),
раздел «Подтверждение framing живым трёхдатчиковым BLE-тестом»); повторное
расхождение между платформами тем более вероятно, если не зафиксировать
единый источник истины.

Правило: контракт пакета и тестовые векторы (сырые BLE-байты →
ожидаемый нормализованный JSON) должны существовать один раз, версионированно,
и каждая платформенная реализация (браузер, iOS, будущий Android) обязана
проходить одни и те же векторы перед релизом. Версия адаптера
(`adapter_version` в `RawIMUPacket`) обязана отличаться по платформе, чтобы
инцидент можно было проследить до конкретного клиента.

## Открыто

- Общие тестовые векторы (raw bytes + JSON) пока не вынесены в отдельный
  package — сделать при добавлении первого не-Python клиента.
- Нативный companion-клиент не спроектирован; появляется только если
  потребуется поддержка iOS/Safari.
